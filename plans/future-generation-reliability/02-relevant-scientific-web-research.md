# 02 — Тематически релевантный и научно надёжный веб-поиск

## Роль

Реализуй только получение и отбор WEB-источников для новых генераций. Не меняй provider-failure семантику из пункта 01 и не перерабатывай layouts/изображения из последующих пунктов.

## Проблема

Для темы «Космос — планета Сатурн» были сохранены ссылки о станциях метро «Академическая». Они появились в режиме `with_sources`, стали опорой для сюжета и отравили видимый текст. Текущая эвристика извлекает поисковую тему из длинного пользовательского промпта, не гарантирует совпадение результатов с темой и сохраняет все непустые результаты Tavily.

## Результат

Новые генерации должны:

- извлекать предмет темы прежде всего из явного поля/фразы «по теме: …», а не из эпитетов в инструкции («академическая», «студенческая» и т. п.);
- отбрасывать результат, если title/url/excerpt не имеют достаточной семантической связи с темой;
- ранжировать научные домены: NASA, ESA, университеты и научные издатели/журналы, государственные и профильные космические агентства; общие энциклопедии — резервно; поисковые каталоги, карты, словари и случайные страницы — не использовать как фактическое основание;
- если после фильтра остаётся ноль WEB-источников, продолжать новый job с корректной AI-речью и пустым набором web sources; не использовать нерелевантные данные и не делать job failed только из-за отсутствия WEB;
- сохранять только отобранные источники и не показывать/не цитировать отброшенные.

## Обязательное исследование

Прочитай `AGENTS.md`, README пакета, `git status --short`, затем:

- `apps/worker/src/tasks/web-search.ts` и его tests;
- `prepareGenerationSources(...)` в `apps/worker/src/tasks/generation.ts` и его tests;
- источники в shared contract и места сохранения в Prisma/API;
- `buildResearchBrief`, narrative-plan builders и source refs;
- фактический формат Tavily result и существующую нормализацию URL.

Не полагайся на статический allowlist, который сделает поиск бесполезным. Нужны понятный domain-quality score, topic-relevance score и детерминированные пороги, покрытые тестами.

## План реализации

1. Выдели тестируемое извлечение `topic`: приоритет явного шаблона `по теме:`/`тема:` с безопасной границей, затем краткого project title, затем существующей эвристики. Убери из query директивы и creation brief. Не ломай английские запросы.
2. Перед сохранением Tavily results введи детерминированный фильтр релевантности. Проверяй нормализованные значимые токены темы против title, URL и excerpt; учитывай именованные сущности/устойчивые словосочетания. Один общий токен недостаточен для принятия результата.
3. Добавь ranking качества домена. Научные/первичные домены получают приоритет; Wikipedia — ниже; карты, каталоги, словари, SEO/генерические аггрегаторы получают жёсткий reject или нулевой приоритет. Логи должны объяснять категории reject только технически, без пользовательского шума.
4. Передай в generation только принятые источники. При пустом массиве используй принятую narration/проектный prompt как допустимую основу; проверь, что путь не требует fake source и не вводит неподтверждённых точных фактов.
5. Сохрани текущий принцип: пользовательские загруженные материалы не выбрасываются из-за ошибки веб-поиска.

## Тесты

- Точный запрос для длинного русского prompt о Сатурне содержит «Сатурн», а не «академическая».
- Результаты про «Академическую» станцию метро, карту и словарь отклоняются.
- NASA/ESA и домен университета по Сатурну принимаются и ранжируются выше вторичных страниц.
- Нерелевантная страница с частично совпадающим словом не проходит порог.
- Пустой результат после фильтра не создаёт WEB-source и позволяет generation source preparation вернуться к корректному prompt/accepted speech пути.
- Загруженный source остаётся доступным, если поиск вернул только reject.
