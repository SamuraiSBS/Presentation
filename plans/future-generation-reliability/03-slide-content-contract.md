# 03 — Контракт содержимого учебного слайда

## Роль

Реализуй только контракт содержимого для **будущих** учебных презентаций: один тезис плюс 2–3 буллета на большинстве content-слайдов. Не меняй источники, провайдеры и загрузку изображений.

## Целевой опыт

Слайд понятен зрителю без докладчика, но не дублирует полный текст речи:

- самостоятельный тезис — одно законченное, конкретное утверждение;
- 2–3 буллета, каждый добавляет факт, объяснение, пример или следствие;
- без обрывков, мета-фраз («контекст задаёт…», «каждый пункт…») и повторов;
- `speakerNotes`/`speechScript` содержат подробную естественную речь и не теряются при repair;
- титульный и финальный слайд могут быть компактнее, но content-слайд не может состоять из одного пустого лозунга.

## Обязательное исследование

Прочитай `AGENTS.md`, README пакета, `git status --short`, затем:

- `apps/worker/src/tasks/presentation/prompts/builders.ts` и `planning/builders.ts`;
- `normalization/presentation.ts` — где формируются thesis/bullets и fallback text;
- `presentation-quality.ts` и `quality/orchestration.ts`;
- `packages/shared/src/presentation/**` contracts;
- `presentation.test.ts`, `presentation-quality.test.ts` и выбранные shared tests.

Проверь различия между title/content/summary slideKind. Не требуй 3 буллета там, где учебная задача честно требует единственной формулы, цитаты или диаграммы; вместо этого должны быть доступные условия-исключения с явным semantic reason.

## План реализации

1. Добавь/уточни generation prompt и slide text plan так, чтобы модель создавала тезис + 2–3 отдельных support points для content-слайда. Каждый буллет должен быть конкретным для темы и не повторять тезис другими словами.
2. Усиль детерминированный quality gate: определить sparse/generic visible content, число полезных буллетов, законченные предложения и связность с accepted narration/narrative plan. Не измеряй лишь количество символов.
3. Сделай локальный repair консервативным: он может проецировать текст из уже принятой narration на видимые thesis/bullets, но не должен выдумывать факты. Если из narration нельзя построить достаточный content-слайд, подними качественную ошибку на provider stage, согласно пункту 01.
4. Сохрани `generatedText`, `speakerNotes`, `speechScript`, source refs и custom canvas. Новый контракт применяется только к автоматически созданным canvas для новых jobs.
5. Не уменьшай размер шрифта, чтобы спрятать лишний текст: компактность достигается смысловой редактурой и layout, не сжатием.

## Тесты

- Валидный content slide с тезисом и двумя независимыми буллетами проходит.
- «Один общий лозунг», шаблонный тезис и пустые/дублирующие буллеты не проходят.
- Обрывок предложения и буллет, копирующий thesis, не проходят.
- Локальная проекция из принятой narration формирует 2–3 релевантных пункта без изменения исходной речи.
- Title/summary и обоснованная диаграмма не получают ложный failure.
- Существующие пользовательские canvas не меняются.
