# 11 — Quality-first контракт длительности для 10-слайдовой речи

## Роль и границы

Выполни только этот пункт в новом чате Codex после 01–10. Сначала прочитай `AGENTS.md`, README пакета, предыдущие планы, `git status --short` и текущий код. Не меняй чужие файлы вне scope и не откатывай рабочее дерево.

Решение продукта: для 10-слайдовой университетской презентации естественная речь важнее искусственного достижения 1430 слов. Yandex остаётся единственным автором. Дополнительный вызов Yandex допустим при браке, но локальный padding запрещён.

## Текущий контракт и проблема

`packages/shared/src/generation/speech-timing.ts` задаёт для 10 слайдов 10–12 минут, цель 11 минут/1430 слов, 90 слов на обложку, 150 на каждый content slide и 140 на conclusion. `NARRATION_SYSTEM_PROMPT` называет это жёстким контрактом, а validation отклоняет текст короче 10 минут.

Этот контракт создаёт стимул дописывать слабый текст вместо того, чтобы принять хороший, немного более короткий доклад. Предыдущий локальный padding был недопустимым следствием такого подхода.

## Цель

Ввести согласованный quality-first контракт **только для 10-слайдовой university-student narration**:

- допустимый диапазон: 9–12 минут, то есть 1170–1560 слов при 130 словах/минуту;
- целевой объём: 10 минут, 1300 слов;
- распределение цели: 80 слов для title, 140 для каждого из восьми content slides и 100 для conclusion;
- качество, связность и grounding выше стремления ровно к target;
- выход ниже 9 минут по-прежнему получает ограниченный Yandex rewrite/recovery либо safe `failed`, но никогда не локальный padding.

Не меняй контракты 6-, 8-, 12- и 14-слайдовых сценариев без отдельного продуктового решения. Не подменяй пользовательский явно заданный другой формат, если в будущем код уже поддерживает такой override.

## Реализация

### 1. Единый shared источник правды

Обнови только 10-slide preset в `packages/shared/src/generation/speech-timing.ts`. Сохрани вычисление минут через 130 words/minute и shared exports. Проверь всех потребителей timing budget, чтобы prompt, narrative plan и validator получили одинаковые min/target/max и per-slide targets.

### 2. Изменить язык prompt, а не только числа

В `apps/worker/src/tasks/presentation/constants.ts` и `prompts/builders.ts` замени семантику «hard contract любой ценой» на качество-ориентированную:

- стремиться к цели распределённо по смыслу;
- не заполнять слабые места повтором, переходной формулой или мета-комментарием;
- лучше дать компактное, содержательное объяснение внутри допустимого диапазона;
- при недостатке содержания переписать section естественно через Yandex, а не добавлять слова локально.

Не ослабляй требование к полным предложениям и предметному объяснению.

### 3. Согласовать validation и UI

Убедись, что `validateNarrationSections(...)`, quality checks, narration prompt, narrative-plan targets и отображаемые labels берут budget из shared helper. Если UI показывает старый диапазон 10–12 для 10 slides, обнови только отображение, которое действительно использует этот shared preset; не дублируй строку в web и worker.

### 4. Не возвращать padding

`completeYandexNarrationDuration(...)` или функциональный эквивалент не должен появиться снова. При 1170+ словах естественная речь проходит duration check; при более коротком тексте действуют только Yandex recovery из пункта 09 или safe failure.

## Тесты

Добавь/обнови unit tests, доказывающие:

1. 10 slides дают min 1170, target 1300, max 1560 и targets 80/140/100.
2. 9-минутный валидный текст проходит, а текст ниже 9 минут получает duration issue.
3. 12-минутная граница сохраняется.
4. Prompt содержит quality-first требования и новые значения, но не содержит прежнего требования `hard contract` для этого режима.
5. Narrative-plan allocation суммируется в 1300.
6. Другие presets не меняются.
7. Duration recovery не вставляет локальные слова/plan metadata.

## Проверка и приёмка

Запусти focused tests shared и worker, затем:

`npm run typecheck -w @studydeck/worker`

`npm run typecheck -w @studydeck/web`

`npm run build -w @studydeck/shared`

`docker compose config --quiet`

`git diff --check`

Не выполняй paid Yandex runtime test и не пересобирай Docker без отдельного пользовательского запроса.

Итог принимается, только если 10-slide speech может быть немного короче прежнего минимума, оставаясь естественной, предметной и полной; все потребители используют один shared timing budget; плохой текст не проходит только из-за количества слов; нет OpenAI/demo fallback, локального padding, обхода quality/release gate или изменений других slide-count presets.
