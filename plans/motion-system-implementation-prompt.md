# Codex prompt: внедрение motion-системы в StudyDeck AI

Ты работаешь в репозитории `D:\presentation`. Реализуй единую систему интерфейсных анимаций в основном Next.js-приложении `apps/web`.

Перед началом прочитай корневой `AGENTS.md` и соблюдай его требования. Не изменяй legacy-приложение в корне репозитория. Сохраняй существующую бизнес-логику, API, React Query, Tiptap и Radix UI.

## Исходное состояние

- Проект использует Next.js App Router.
- Пакет `motion` уже установлен в workspace `@studydeck/web`.
- Основные глобальные стили находятся в `apps/web/src/app/globals.css`.
- Общая оболочка находится в `apps/web/src/components/app-chrome.tsx`.

## Согласованное направление дизайна

Интерфейс должен быть живым и дружелюбным, но быстрым и спокойным:

- без прыжков крупных блоков;
- без сильного масштабирования;
- шапка и навигация остаются неподвижными при переходах;
- анимируется только содержимое страницы;
- крупные карточки при hover поднимаются максимум на `2px`, меняют тень, фон или обводку, но не масштабируются;
- небольшие кнопки могут использовать `scale: 1.01–1.02`;
- первые 6–8 элементов списка появляются каскадом, остальные сразу;
- при повторном открытии используется короткое проявление, а не полный каскад;
- добавленные, удалённые и переставленные элементы анимируются отдельно;
- в редакторе анимируется интерфейс, но не объекты внутри слайда;
- административные страницы используют ту же систему с вдвое меньшей амплитудой.

Базовые скорости:

- кнопки и небольшие контролы: `120–160ms`;
- карточки, меню и панели: `180–240ms`;
- первое появление страницы: `280–320ms`;
- переключение слайдов: `180–220ms`.

Перемещения:

- содержимое страницы: `8–12px`;
- интерфейс редактора и панели: `6–16px`;
- административная часть: `4–6px`.

## Правила реализации

Используй Motion for React для появления, исчезновения, layout-перестановок, каскадных списков, смены состояния и интерфейса редактора:

```tsx
import { AnimatePresence, motion, MotionConfig } from "motion/react";
```

CSS оставь для hover, focus, цветов, теней, обводок и простых индикаторов.

Обязательно:

1. Подключи `MotionConfig reducedMotion="user"` на подходящем клиентском уровне.
2. Не превращай серверные страницы в client components без необходимости — создавай небольшие клиентские обёртки.
3. При reduced motion отключай transform/layout-анимации и сохраняй короткий fade.
4. Предпочитай `transform` и `opacity`; не анимируй геометрические CSS-свойства без необходимости.
5. Не ухудшай ввод в Tiptap и не заставляй весь редактор перерендериваться ради анимации.
6. Не дублируй уже существующие CSS-переходы и keyframes.
7. Не устанавливай дополнительные animation/toast-библиотеки без явной необходимости.

## Этап 7. Редактор

Основной файл: `apps/web/src/components/project-editor.tsx`. Сначала изучи связанные компоненты.

Не анимируй текст, изображения, диаграммы и другие объекты внутри готового слайда. Анимируй оболочку редактора.

### Переключение слайдов

- рабочая область: `180–220ms`;
- opacity и сдвиг `6–8px`;
- направление сдвига зависит от движения вперёд/назад;
- выбранная миниатюра плавно меняет фон и обводку.

### Добавление и удаление

- новая миниатюра появляется со сдвигом и прозрачностью;
- удаляемая миниатюра быстро исчезает и может слегка уменьшаться;
- соседние миниатюры плавно занимают место;
- после удаления рабочая область переходит к соседнему слайду без скачка.

### Панели и меню

- боковые панели выезжают на `12–16px`;
- маленькие меню: opacity и `scale: 0.98 → 1`;
- секции плавно раскрываются;
- backdrop: `160–200ms`;
- модальные окна не должны заметно увеличиваться.

### Сохранение

Добавь компактный статус рядом с названием проекта:

```text
Сохранение…
Сохранено
Ошибка сохранения
```

- «Сохранение…» показывает мягкий индикатор;
- «Сохранено» показывает галочку и затем исчезает;
- ошибка остаётся видимой и при возможности даёт повторить действие;
- не показывай toast после каждого автосохранения.

## Критерии готовности

- Все пользовательские страницы используют единый язык движения.
- Header и navigation не перезапускают анимацию при переходах.
- Крупные блоки не прыгают и не масштабируются.
- Длинные списки не задерживаются каскадом.
- Добавление, удаление и перестановка элементов выглядят плавно.
- Редактор анимирует только интерфейс.
- Автосохранение имеет понятный статус.
- Важные фоновые события используют доступные уведомления.
- Административная часть остаётся сдержанной.
- Reduced motion работает.
- Бизнес-логика не изменена.
- TypeScript и целевые тесты проходят.
- Посторонние изменения пользователя не затронуты.
