# Промты для внедрения библиотек в StudyDeck

В этой папке лежат готовые промты для Codex по внедрению или усилению библиотек в монорепозитории StudyDeck AI: `D:\presentation`.

Промты сгруппированы по классам, чтобы можно было брать не весь список сразу, а работать с одной продуктовой зоной за раз.

## Продуктовое направление

StudyDeck должен в первую очередь делать:

- стильные русскоязычные презентации для защиты и выступлений;
- более качественную генерацию, даже если она занимает дольше;
- хороший результат по короткой теме без загруженных файлов;
- минимум ручного редактирования, в основном текст слайдов и речь;
- сильную структуру доклада, фактическую опору, хорошую речь и визуальный ритм.

## Классы

1. `01-ai-generation`
   - AI-вызовы, строгая валидация, исследование темы и фоновые задачи генерации.
   - Начинай отсюда, если цель - улучшить качество самих презентаций.

2. `02-editor-visuals`
   - Редактирование текста, диаграммы, обработка изображений и будущие графовые визуалы.
   - Начинай отсюда, если нужно улучшить то, что пользователь может править, или то, что видно на слайдах.

3. `03-frontend-ui`
   - Загрузка данных на фронтенде, UI-компоненты, доступность и иконки.
   - Начинай отсюда, если нужно сделать веб-интерфейс спокойнее, понятнее и приятнее.

4. `04-observability`
   - Мониторинг ошибок, структурные логи и трассировка.
   - Начинай отсюда, если сложно понять, почему ломается генерация, экспорт или API.

5. `05-testing`
   - E2E-тесты и детерминированные unit/integration-тесты.
   - Начинай отсюда, если нужно укрепить проект перед крупными изменениями.

## Как использовать

Открой нужный файл и скажи Codex:

```text
Реализуй план из plans/library-implementation-prompts/<class>/<file>.md
```

Для frontend-задач используй `npm run dev:web:fast` и проверяй результат на `http://localhost:3020`.

Для изменений в worker/API пересобирай только затронутые Docker-сервисы, если нужна production-like проверка.
