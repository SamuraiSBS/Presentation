# 05 — коммит принятого набора и неплатная post-commit проверка

## Предусловие

Запускай этот prompt только после вердикта координатора `Commit readiness принят`. Приложи отчёт review, где явно перечислены разрешённые к коммиту файлы.

## Цель

Создать один узкий коммит только с принятым набором генерационного hardening и доказать, что HEAD содержит нужный diff. Это не повторная реализация и не новый E2E/AI-прогон.

## Порядок

1. Прочитай `AGENTS.md`, README пакета, отчёт commit-readiness и выполни `git status --short`.
2. Сверь список файлов с разрешённым review scope. Не добавляй ничего, чего там нет; в частности, никогда не добавляй `.audit-bmw/tmpw120oeib/enlarged.pptx`.
3. Добавь только явно разрешённые файлы, создай один коммит с сообщением, отражающим retry/cost/recovery hardening.
4. Зафиксируй hash коммита, `git show --stat --oneline HEAD` и итоговый `git status --short`.
5. Выполни только неплатные проверки, перечисленные в принятом review (например, целевые tests/typechecks или health check уже поднятого API). Не запускай AI/Tavily, не создавай новый проект и не делай Docker rebuild/restart без отдельного указания.

## Критерии приёмки

- Создан ровно один коммит только из одобренных файлов.
- Чужие изменения остались вне коммита.
- Проверки после коммита успешны либо их известные несвязанные сбои честно отделены.
- Внешние расходы: `0 RUB`.
- Нет push, remote deploy или второго live-run.

## Отчёт и остановка

Передай координатору commit hash, список файлов коммита, результаты команд, `git status --short` и строку `0 RUB: новые AI/Tavily вызовы не выполнялись`.

После отчёта остановись. Remote deploy выполняется только отдельным последующим запросом пользователя.
