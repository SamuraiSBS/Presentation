# 01 — единый лимит запуска и повторное использование источников

## Цель

Устранить финансовый и recovery-дефект: повторный presentation job того же пользовательского запуска не должен создавать независимый budget envelope, повторно тратить Tavily или обходить общий лимит. После сбоя система должна иметь один понятный attempt group с фактическим расходом, резервами и остатком.

## До начала

Прочитай `AGENTS.md`, `plans/generation-recovery-hardening/README.md`, текущие worker/API contracts и `git diff`. В worktree уже могут быть незавершённые изменения этой области: сначала пойми их намерение и доработай их, не переписывая и не теряя чужую работу.

## Scope

Разрешены только минимально необходимые изменения в shared generation/cost contracts, API создания/повтора проекта и worker cost/source orchestration с их тестами. Не чинить локальную сборку презентации в этом prompt — это Prompt 02.

Не выполнять Docker build/restart, миграции, реальные AI/Tavily вызовы, commit, deploy или любые платные прогоны.

## Обязательное поведение

1. Введи или доведи до конца явную связь всех retries одного пользовательского запуска с общим attempt group / общим бюджетом. Нельзя считать новый `presentationJobId` новым разрешением на полный лимит.
2. Перед каждой платной операцией проверяй суммарный settled + reserved + потенциальный расход группы. Новая операция не стартует, если она превысит cap.
3. Не допускай старой ошибки, при которой поиск «активного envelope без `presentationJobId`» после первой неудачи создаёт новый envelope и умножает лимит.
4. Сохраняй успешный source snapshot и его provenance. После успешного Tavily-поиска retry презентации должен reuse тот же snapshot без нового поиска и без нового расхода Tavily.
5. Ретраи остаются ограниченными и наблюдаемыми: попытка, причина, reservation/settlement, общая сумма и остаток должны быть диагностируемы без секретов.
6. Не ослабляй защиту от параллельного overspend и не делай «примерную» проверку вместо атомарной/идемпотентной, где она нужна текущей архитектуре.
7. Сохрани поддержку текущих провайдеров, но не добавляй demo fallback в production path.

## Обязательные тесты

Добавь или обнови детерминированные unit/integration tests, доказывающие минимум:

- один проект и несколько presentation retries используют один суммарный лимит;
- сценарий ранее наблюдавшегося перерасхода (несколько presentation retries после принятой речи) не может превысить cap;
- успешный source snapshot переносится/reuse-ится и повторный retry не вызывает Tavily;
- insufficient remaining budget предотвращает новый платный provider call и передаёт управление recovery path;
- нормальный первый запуск по-прежнему резервирует и учитывает расходы корректно.

Запусти целевые typecheck/tests для затронутых packages. Если полный уже существующий тестовый файл падает по несвязанной старой причине, отдели её точным evidence и не маскируй.

## Критерии приёмки

- Нет пути, где один пользовательский запуск создаёт независимый полный cost cap на каждый presentation retry.
- Snapshot реальных источников переживает retries и не вызывает повторный поиск.
- В diff нет demo/mock/фиктивных источников, миграций, Docker-операций и несвязанных рефакторингов.
- Тесты доказывают и лимит, и source reuse.
- Стоимость внешних вызовов для этого этапа: `0 RUB`.
