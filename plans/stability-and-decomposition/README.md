# StudyDeck: стабильность и безопасная декомпозиция

В этой папке находятся четыре самостоятельных плана-промта для Codex. Каждый файл рассчитан на отдельный новый чат и содержит достаточный контекст, чтобы после проверки живого состояния репозитория сразу перейти к реализации.

## Рекомендуемый порядок

1. [`01-ui-stability-and-quality-gates.md`](./01-ui-stability-and-quality-gates.md) — исправить пользовательские сбои, мобильный сценарий, lint и E2E-базу.
2. [`02-frontend-decomposition.md`](./02-frontend-decomposition.md) — безопасно разделить `globals.css` и `project-editor.tsx` без изменения поведения.
3. [`03-shared-contracts-decomposition.md`](./03-shared-contracts-decomposition.md) — превратить `packages/shared/src/index.ts` в стабильный barrel и тематические модули.
4. [`04-presentation-worker-decomposition.md`](./04-presentation-worker-decomposition.md) — разделить крупный worker-пайплайн генерации, сохранив качество и провайдеры.

## Как использовать

В новом чате передайте Codex содержимое только одного файла и попросите реализовать его полностью. Не запускайте пункты 2–4 параллельно: они затрагивают связанные импорты и проверки, поэтому последовательная реализация сильно упрощает поиск регрессий.

Каждый следующий чат должен считать фактический код источником истины. Если предыдущий пункт уже изменил структуру файлов, нужно адаптировать пути, но сохранить цели и ограничения соответствующего промта.

## Общая логика

```text
пользовательская стабильность
  -> безопасные frontend-границы
  -> безопасные shared-контракты
  -> безопасные worker-границы
  -> дальнейшие улучшения качества содержания
```

Декомпозиция в этих документах не является самоцелью. Она должна сократить риск изменений в ключевых продуктовых направлениях: качестве содержания, автоматической проверке презентаций, простом редакторе и подготовке StudyDeck к первым платным пользователям.
